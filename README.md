# 🧾 TripLedger（旅帳本）

> 把出國旅遊拍下的紙本收據和信用卡對帳單自動對起來的 Mac 小工具：辨識收據、翻成中文、分類、比對刷卡紀錄，最後匯出成一份完整的旅遊花費表。
> 用的是 Apple 內建在 macOS 裡的 AI，完全離線、不上傳、不用付費。
> *A macOS app that matches your travel receipts with credit-card statements, using Apple's on-device AI.*

![platform](https://img.shields.io/badge/platform-macOS%2027%2B-blue) ![chip](https://img.shields.io/badge/chip-Apple%20silicon-black) ![swift](https://img.shields.io/badge/swift-5-orange) ![license](https://img.shields.io/badge/license-MIT-lightgrey)

> ⚠️ **目前是開發中的 0.1 版，還沒有可以下載的正式版本。** 現在要自己用 `安裝.command` 編譯安裝（見[第 2 節](#2-安裝)）。
> 已完成「階段 0」（測試 Mac 內建的文字辨識讀韓文收據準不準），正在做「階段 1」：收據入帳的 Mac App（見[第 10 節](#10-開發藍圖)）。各版改了什麼見 [CHANGELOG](CHANGELOG.md)。
> 下面的畫面說明都還沒有截圖，等實機測試完成後會補上示意圖。
> 這個工具的構想來自作者整理 2026 年 10 月釜山旅遊花費的經驗：約 35 張韓文收據，對照星展、台新、永豐三家信用卡對帳單，手動整理非常花時間。

## 1. 這是什麼？能幫我什麼？

出國回來整理花費，通常要做這幾件事：

1. 一張一張看收據（還常常是看不懂的外文）。
2. 打開好幾家銀行的信用卡對帳單，找出是哪一筆。
3. 把外幣金額、換算的台幣、海外刷卡手續費記下來。
4. 判斷這筆算吃的、買的、還是玩的。
5. 找出「有收據但帳單上沒有」或「帳單上有但想不起來是什麼」的消費。

**TripLedger 想把這些步驟自動化**，你只需要確認它不確定的地方。

| 步驟 | 誰來做 |
|---|---|
| 從收據照片讀出店名、時間、金額、刷哪張卡 | 文字辨識＋程式規則 |
| 把韓文店名、品項翻成簡短的中文（例：거대곰탕 → 巨大熬湯-熬湯2碗+煎餃） | Mac 內建的 AI |
| 判斷消費類別（食衣住行樂…） | Mac 內建的 AI＋常見店家清單 |
| 讀取信用卡對帳單 PDF，算出含手續費的台幣 | 程式規則（每家銀行各一套） |
| 收據和對帳單比對 | 程式規則（金額、日期、卡號前幾碼） |
| 對不上的、不確定的 | **標成紅字，請你確認** |

| 你的情況 | 適合嗎 |
|---|---|
| 出國刷卡、留了紙本收據，想整理成一張花費表 | ✅ 這就是它的用途 |
| 和旅伴出遊，一個人記帳，要算誰該給誰多少 | ✅ 規劃中（分帳功能） |
| 台灣日常記帳、電子發票 | ⚠️ 目前不支援，之後可能擴充 |
| 使用 iPhone、Intel Mac、Windows、Android | ❌ 只支援 Apple 晶片的 Mac（見下一節） |

## 2. 安裝

**需要**：
- Apple 晶片（M1、M2、M3…）的 Mac
- macOS 27 以上
- 已開啟 **Apple Intelligence**（「系統設定 → Apple Intelligence 與 Siri」）

（查看方式：左上角  →「關於這台 Mac」。）

**現在（開發版）的安裝方式：自己編譯**

1. 下載專案：到 [GitHub 專案頁](https://github.com/WebberningMoney/trip-ledger) 按綠色的 **Code → Download ZIP** 並解壓縮；
   或在終端機輸入 `cd ~/Desktop && git clone https://github.com/WebberningMoney/trip-ledger.git`。
2. 雙擊資料夾裡的 **`安裝.command`**。它會編譯、跑自我測試，沒問題才把 **TripLedger** 放進「應用程式」並打開。
   - 第一次可能會跳出「**命令列開發者工具**」的安裝視窗：這是 Apple 官方的免費工具，按「安裝」，裝好後再雙擊一次 `安裝.command`。
   - 如果 Mac 說「無法打開」：在 `安裝.command` 上按右鍵 →「打開」。
3. 之後要更新：重新下載（或在資料夾裡執行 `git pull`），再雙擊一次 `安裝.command`。你的帳本資料不會受影響。
4. 要移除：雙擊 `解除安裝.command`。它會先問你確定要移除 App，再另外問要不要刪除帳本資料（預設保留）。

**之後正式版的安裝方式**（還沒發佈）：

1. 到 [GitHub Releases](https://github.com/WebberningMoney/trip-ledger/releases) 下載最新版的 `TripLedger.zip`。
2. 雙擊解壓縮，把 **TripLedger** 拖進「應用程式」資料夾。
3. 第一次打開時，macOS 可能會說「無法打開」或「無法確認開發者」。
   這是因為這個 App 不是從 App Store 來的（作者沒有付費申請 Apple 開發者帳號），macOS 會先擋下來。請打開
   「系統設定 → 隱私權與安全性」，往下捲，按「**仍要打開**」。之後就可以正常打開。

> 💡 不需要安裝 Xcode，也不需要打開終端機。

## 3. 每天怎麼用

> 0.1 版還沒在真的 Mac 上完整操作過，畫面細節可能會調整。

**旅途中**：照常用 iPhone 相機拍下每一張收據就好，不需要安裝任何 App。

**回國後，打開 TripLedger：**

```
┌ 行程 ─────┬ 日期  時間  項目               付款   金額    分類 ┬ 收據照片 ──────────┐
│ 範例行程   │ 3/1  12:30 星巴克-拿鐵         刷卡   6,500  食  │                    │
│           │ 3/1  15:10 Olive Young-面膜    刷卡  24,000  衣  │ 中文店名 [      ]  │
│           │ 3/2  10:05 （紅字）某某餐廳-?   現金  18,000  食  │ 品項     [      ]  │
│ ＋新增行程 │ 3 筆・1 筆待確認               合計 KRW 48,500  │ [儲存] [確認這筆]  │
└───────────┴─────────────────────────────────────────────────────┴────────────────────┘
```

1. **新增行程**：左下角「新增行程」（或選單「檔案 → 新增行程…」、⌘N），例如「2026 釜山」。
2. **匯入收據照片**，三種方法都可以：
   - 上方「**匯入照片…**」：選照片或整個資料夾。
   - 上方「**從「照片」挑選**」：直接從 Mac 的「照片」App 挑（iPhone 拍的照片有開 iCloud 同步就會出現）。
   - 把照片或資料夾**拖到中間的表格**。

   原始照片只會被讀取，App 會複製一份到自己的資料夾。
3. **等它辨識**：每張收據會變成一筆，自動填入日期、時間、金額、付款方式、卡號前 6 碼、店名、品項和分類。
4. **看紅字**：紅字代表「有欄位讀不到」或「店名、類別是自動判斷的」。點那一筆，右邊會顯示收據照片和欄位：
   - 改好按「**儲存**」（⌘S）；確定沒問題按「**確認這筆**」（⌘Return），紅字就會消失。
   - **改過的店名和分類會被記住**：下次遇到同一家店（用收據上的營業登記號碼辨認）會自動套用，
     同一個行程裡還沒確認的同一家店也會一起改。
   - 讀不到日期或金額時，右邊會顯示「AI 看照片的猜測」，只供參考，要按按鈕才會填入。
5. **匯出**：上方「**匯出 Excel…**」。紅字的那筆在 Excel 裡也是紅字，日期、時間、金額都是 Excel 認得的格式，可以排序和加總。
   已經有同名檔案時會自動改名，不會覆蓋。

**店名是怎麼來的**（依順序，找到就停）：

1. 你改過的店家（記住的店家）。
2. 內建的常見連鎖店清單（Olive Young、CU、Daiso、星巴克、樂天免稅店…，見 `Resources/chains.json`）。
3. 用 Mac 內建的翻譯，把收據上印的韓文店名翻成繁體中文。第一次會跳出 macOS 的視窗，請你下載「韓文」和「繁體中文」語言包。

## 6. 效果與限制

**階段 0 的實測**（作者的 Mac：M2 Pro、macOS 27.2.1；2026 年 10 月釜山旅遊的 37 張真實韓文收據，和人工確認過的答案比對）：

| 欄位 | 文字辨識＋規則（正式版會用的方法） | AI 直接看照片（只當參考） |
|---|---|---|
| 日期 | 36／37 | 16／37 |
| 時間 | 36／37 | 15／37 |
| 金額 | 36／37 | 29／37 |
| 卡號前 6 碼 | 29／31（收據上沒印卡號的不算） | 6／31 |
| 付款方式（刷卡／LINE Pay／現金） | 33／34 | 28／34 |
| 消費類別（AI 判斷） | 21／36；把 AI 回答的「飲」算成「食」、「藥」算成「他」後是 27／36 | |

- 速度（同一台 Mac）：文字辨識平均每張約 0.4 秒，AI 整理店名和類別約 1.7 秒。
- AI 直接看照片時，除了數字常錯，還可能**編出收據上沒有的店名**，所以正式版的數字一律用規則讀，AI 的答案只當參考。
- 只測過這 37 張、這一台 Mac；其他國家、其他店家的收據，正確率可能不一樣。

目前已知可能的限制：

| 情況 | 可能的影響 |
|---|---|
| 熱感紙收據褪色、折到、捲曲 | 文字辨識可能整段漏讀（實測有一張漏掉上半部的卡號），會標紅請你確認 |
| 只有「中間結帳單」沒有刷卡資訊的收據 | 無法判斷刷哪張卡，只能靠金額比對 |
| 數字被讀錯一個字 | 實測有一張卡號 548368 被讀成 548360，規則沒辦法發現 |
| 同一天、同金額的兩筆消費 | 可能配錯，會請你確認 |
| 對帳單上的店名是代收公司（例如支付平台名稱） | 看不出實際店家，需要你補充 |
| AI 取的店名 | 實測約一半可直接用，也有取錯的（例如把 Miffy 店叫成星巴克）；正式版會改用翻譯＋常見店家清單＋記住你改過的名稱 |

## 7. 名詞小辭典

| 名詞 | 白話解釋 |
|---|---|
| **對帳** | 把收據和信用卡帳單一筆一筆對起來，確認每筆錢都有著落 |
| **文字辨識**（OCR） | 從照片裡把字讀出來，變成電腦可以處理的文字 |
| **裝置端 AI** | 在你自己的電腦上執行的 AI，不用把資料傳到網路上 |
| **Apple Intelligence** | Apple 內建在 Mac、iPhone 裡的 AI 功能，需要在系統設定裡開啟 |
| **海外刷卡手續費** | 在國外刷卡時，銀行另外收的費用，通常約為台幣金額的 1.5% |
| **原幣** | 消費當地的貨幣，例如韓元 |
| **營業登記號碼** | 韓國收據上的「사업자번호」（例如 217-17-25290），每家店不一樣，用來辨認是不是同一家店 |
| **ad-hoc 簽章** | 不用付費的「臨時」程式簽名。macOS 第一次會擋，需要手動允許 |
| **編譯** | 把人寫的程式原始碼，轉換成電腦可以執行的程式 |

## 8. 隱私：它會連到哪些地方？

**辨識和整理收據時哪裡都不連。** 收據照片、消費紀錄都只在你的 Mac 上處理，不會上傳到任何地方，也不收集任何使用資料。

唯一可能連網的時候：

- **第一次翻譯店名時**，macOS 會跳出視窗請你下載「韓文」和「繁體中文」的翻譯語言包。這是向 Apple 下載語言包，按下載才會下載；
  下載之後翻譯完全在你的 Mac 上進行，不會把店名傳出去。不想下載可以按取消，店名會先顯示韓文原文，你可以自己改。
- 裝置端 AI（Apple Intelligence）的模型由 macOS 管理下載，TripLedger 不會另外下載任何東西。

資料存在哪裡：

- 帳本（行程、消費、App 複製的收據照片、記住的店家）都在 `~/Library/Application Support/TripLedger/`。
- **不會修改你原本的收據照片**，只會讀取並複製一份。
- 刪除行程或消費時，只刪 App 自己複製的照片；`解除安裝.command` 會另外問你要不要刪除帳本資料。
- 之後的對帳單功能：對帳單 PDF 的密碼只在讀取時使用，**不會儲存**。

## 9. 常見問題

**Q：為什麼不支援 iPhone？**
A：在 iPhone 上安裝非 App Store 的 App，需要付費的 Apple 開發者帳號，或每 7 天重新安裝一次，對一般人太麻煩。所以收據用 iPhone 相機拍，整理在 Mac 上做。

**Q：為什麼要 macOS 27 和 Apple Intelligence？**
A：直接讀收據照片的裝置端 AI，是 macOS 27 才開放給一般 App 使用的功能，而且需要開啟 Apple Intelligence。舊版 macOS 和 Intel Mac 沒有這個功能。

**Q：為什麼不用 ChatGPT、Claude 這類雲端 AI？準確度不是比較高嗎？**
A：雲端 AI 要按用量付費，也要把收據和消費資料傳出去。TripLedger 希望讓每個人都能免費使用，而且資料不離開電腦。

**Q：店名一直顯示韓文？**
A：可能是翻譯語言包還沒下載。可以到「系統設定 → 一般 → 語言與地區 → 翻譯語言」下載「韓文」和「繁體中文」，再重新打開 TripLedger。也可以直接在右邊改成你要的中文名稱，App 會記住。

**Q：分類或店名猜錯了？**
A：在右邊改好按「儲存」。App 會記住這家店，下次自動套用。常見連鎖店的名稱或分類想改，也歡迎到 GitHub 開 Issue，或直接改 `Resources/chains.json`。

**Q：裝置端 AI 顯示不能使用？**
A：請確認「系統設定 → Apple Intelligence 與 Siri」（macOS 27 也可能在「Siri」裡）已開啟、模型已下載完成，而且系統語言和 Siri 語言設成同一個語言。AI 不能用時，日期、金額等欄位一樣會讀，只是店名和分類要自己填。

**Q：我的銀行不在支援清單裡？**
A：可以到 GitHub 開 Issue 告訴我們是哪家銀行。請**不要**直接上傳真實的對帳單，先把姓名、卡號、地址等個資遮蔽。

### 階段 0：收據辨識測試（給開發者）

測試工具會用兩種方法讀收據，再和人工確認過的標準答案比對：

- **方法 A**：文字辨識讀出收據上的字 → 固定規則讀日期、時間、金額、卡號前 6 碼、付款方式 → AI 只負責店名翻譯、品項、消費類別。
- **方法 B**：照片直接交給 AI 讀全部欄位，只拿來和方法 A 比較。

怎麼跑：

1. 把收據照片放進專案資料夾的 `private/receipts/`，標準答案放在 `private/expected.json`（格式見 `docs/ARCHITECTURE.md`）。
   `private/` 不會上傳到 GitHub。
2. 雙擊 **`收據測試.command`**。會自動編譯、跑自我測試、讀每一張收據，最後打開報告 `private/results/report-latest.md`。
   - 第一次可能會跳出「命令列開發者工具」的安裝視窗：按「安裝」，裝好後再雙擊一次。
   - 如果 Mac 說無法打開：在檔案上按右鍵 →「打開」。
3. 報告裡有每個欄位的正確率、每張收據對錯、AI 取的名稱，以及文字辨識讀到的原始內容。

也可以用終端機：`bash scripts/build.sh && bash scripts/selftest.sh`，再執行 `build/receipt-probe`（可用的選項見 `Sources/Probe/main.swift` 開頭說明，例如 `--no-ai` 只測文字辨識和規則）。

## 11. 專案裡有哪些檔案

```text
trip-ledger/
├── README.md              ← 你正在看的這份說明
├── 安裝.command            ← 雙擊安裝（編譯＋自我測試＋放進「應用程式」）
├── 解除安裝.command         ← 雙擊移除（會先確認；帳本資料另外問要不要刪）
├── 收據測試.command         ← 階段 0：雙擊執行收據辨識測試
├── Sources/
│   ├── Core/              ← App 和測試工具共用：文字辨識、規則、AI、店家、資料、匯出 Excel
│   ├── App/               ← Mac App 的畫面（行程清單、消費表格、收據照片與欄位）
│   └── Probe/             ← 階段 0 的測試工具（報告、自我測試）
├── Resources/
│   ├── Info.plist         ← App 的基本資料（名稱、版本、需要的 macOS 版本）
│   └── chains.json        ← 常見連鎖店清單（店名、分類），歡迎補充
├── scripts/
│   ├── build.sh           ← 編譯（App＋測試工具）
│   ├── selftest.sh        ← 自我測試（用假資料檢查規則）
│   └── git-hooks/         ← 開發用：commit／push 前的自動檢查
├── docs/
│   └── ARCHITECTURE.md    ← 給想看懂程式的人：流程圖、規則怎麼判斷、用到哪些技術
├── CHANGELOG.md           ← 每次更新改了什麼
├── CLAUDE.md              ← 給 AI 助理的協作守則
├── LICENSE                ← 授權條款
└── .gitignore             ← 不上傳到 GitHub 的檔案（編譯結果、private/ 裡的真實收據與報告）
```

執行後還會多出 `build/`（編譯結果、紀錄）和 `private/`（真實收據、測試報告），兩者都不會上傳到 GitHub。
